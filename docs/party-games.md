# Shared-device games

## Artwork, sound and game data

The editable drawings live in `scripts/art/arcade.svg` and `scripts/arcade-art.py`. Render them with
`python3 scripts/arcade-art.py` using Pillow and librsvg’s `rsvg-convert`. The exporter writes standalone SVGs for the scimitar, snake head and body, and Tic-Tac-Toe marks.
The app rasterizes them with resvg, applies team ink through SVG currentColor, and caches a bitmap
for the mounted board or preview. Memory cards, moles, rollers and fruit use bitmap atlases. The Basketball atlas projects seams onto a rotating sphere under
a fixed light. Fruit Merge samples contact outlines from the same drawings used on the board.
Impostor draws its catalog portrait on the canvas.

Run `python3 scripts/arcade-sounds.py` to synthesize the arcade cues. Each effect has its own
combination of resonances, air noise and envelopes. Both mobile platforms play the generated
mono 44.1 kHz PCM files. Pool has its own material-based generator described below.

Edit the soccer formations and nine golf courses in `resource/assets/buttonsoccer/formations.json`
and `resource/assets/minigolf/courses.json`. Fruit Duel defines swing timing and the illustrated
blade’s contact edge in `games/fruitduel/src/model.rs`. Impostor’s six language decks live in
`resource/assets/impostor/`. Each offers 192 clues in twelve categories. Category IDs agree across
languages so a player can switch decks and keep their category selection.

## Playing on a shared screen

The app uses a dark control theme. Score cards identify the active turn with a matching title,
colored border and explicit badge; simultaneous games mark all participating players. Result
and pause cards fit their content until the available screen height requires scrolling.
Numeric score fields reserve a stable width and use fixed digit advances; territory always shows
one localized decimal place. Score font size is fitted to the reservation, never the changing value.
Pool has distinct shot, ball/rail impact, pocket, scratch and finish haptics; collisions are rate
limited and scale with impact speed. Other games cue placements, matches/mismatches, mole hits,
control engagement, countdowns, eliminations and pickups. All honor each game's Vibrations toggle.

Pool pockets have flush leather trim on the rail side, inset bevels and woven catch nets. Transient
pocket events preserve the ball's entry position and velocity even when a scratch respots the
cue immediately. The presentation rolls the ball into the throat, shrinks and shades it below
the opening, and settles the net with a timed landing haptic. No foreground rim covers a rolling ball; it crosses the edge at full size before sinking. Reduced Motion uses a short fade.
These effects are not persisted or replayed when restoring a round.

The numbered ball set now uses the conventional seven colors, solids 1–7 and stripes 9–15,
with a plain white cue ball and black eight. The randomized tight rack keeps the eight in the
middle of the third row and opposite groups at the rear corners; other positions are shuffled
as specified in [WPA section 4.2](https://www.wpapool.com/wp-content/uploads/2026/01/2026.01.02-WPA-Rules.pdf).
The app's simplified assigned groups remain Player 1 solids and Player 2/computer stripes,
identified on the scoreboards and in all localized instructions.

Ball orientations are persisted unit quaternions integrated from actual distance and direction
of travel. Number discs and stripe caps are projected onto the visible sphere, including
foreshortening and horizon occlusion. Lighting stays fixed in world space; rebounds change the
rolling axis, resting balls keep their orientation, and pocket effects inherit the entry orientation.

Pool uses ten original PCM Foley assets generated by `python3 scripts/pool-sounds.py`.
Cue tips, ball contacts and rubber cushions each have soft/medium/firm excitations. Actual cue
speed or normal collision speed selects the material's timbre and scales gain; glancing and
separating contacts therefore do not sound like head-on impacts. Playback stays at normal pitch
on every platform. The pocket cue combines rim contact, a low landing and a quieter settling
knock. All clips use generated resource accessors and honor the game's Sounds toggle.

Native portrait-only boards lock rotation for the duration of the game cover and release it
on close. Solitaire, Sudoku, Mines and Charades keep their adaptive/sideways layouts. The iPad
host uses fullscreen presentation so iOS honors these per-game orientation masks.

## Platform catalog behavior

Native iOS, Android, and HarmonyOS show **Players: 1 2 3 4**. Web checks the toolkit's
touch-capability probe after launch, so a narrow desktop window does not become a mobile device.
The count means human players: 1 includes solo games and games with AI; 2 includes two-player
and larger games; 3 and 4 include Memory, Whack-a-Mole, Snakes, Paint Fight, and group Charades.
Tic-Tac-Toe, Pool, and Flipside support at most two. Changing the filter fades/scales changed tiles
in and out, respecting reduced motion. Launch and New Game use the catalog count directly.
Saved rounds resume only when their human count matches the current selection.
Desktop tiles and incoming game links use the same availability rule. Charades, Impostor, Fruit
Duel, Paint Fight, Whack-a-Mole, Snakes, and Basketball Hoops require the mobile profile.

## Crate structure

Each game owns its model, board rendering, input, and tests under `games/`. The editable
arcade illustrations live under `scripts/` and the bundled sheets under `resource/assets/`.
`gamekit` owns the shared scorecards, fitting dialogs, colors, celebration,
feedback and frame scheduler. `game-resources` generates typed accessors from the single app
resource catalog, so game crates have no dependency on the application shell. The shell owns
catalog filtering, navigation, and native orientation policy. The pre-release combined save
formats are intentionally not migrated.

## Validation

```sh
cargo test --workspace --offline
cargo clippy --workspace --all-targets --offline -- -D warnings
day lint
# Use an explicit emulator serial so no connected physical phone is selected.
day launch -t android-material --android-device emulator-SERIAL --locale en \
  --env DAY_GAMES_SEED=15 --script dayscript/catalog.yaml --script dayscript/party.yaml --keep-alive
# iPhone simulator must already be booted.
day launch -t ios-uikit --ios-simulator SIMULATOR-UDID --locale en \
  --env DAY_GAMES_SEED=15 --script dayscript/catalog.yaml --script dayscript/party.yaml --keep-alive
python3 scripts/party-touch-test.py emulator-SERIAL
```

The native test compiles the test-only `TwoFingers.java` helper with the local Android SDK. It
checks two independent held joysticks, a real Pool pullback and settling shot, simultaneous mole
hits, and background save/restore. It operates only on explicitly named emulators. `DAY_CLI`
can select a locally built Day binary. Neither the helper nor test fixtures are bundled in the app.

Rust coverage includes impossible human wins against Tic-Tac-Toe's AI, Memory turn rules and
completion, the mole race and duplicate-hit rejection, simultaneous snake collisions, paint
ownership, timing, release behavior and both pickup effects, Pool pots/scratches/black-ball outcomes, malformed saves, independent finger
ownership/cancellation, and catalog filtering. Screen tests include every new game and its help
and setup surfaces. Browser checks cover desktop, narrow desktop, phone, and tablet profiles.

Run `python3 scripts/board-games-touch-test.py emulator-SERIAL` to exercise input, scoring and
turn changes in Button Soccer, Dots and Boxes, Mini Golf, Fruit Merge and Impostor.
